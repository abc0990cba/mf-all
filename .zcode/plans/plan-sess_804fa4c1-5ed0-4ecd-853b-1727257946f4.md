# Add Alpine.js + jQuery to the mesh (7 → 9 apps)

New pages: **apps/alpine** (port 5180, mf name `alpineApp`) and **apps/jquery** (port 5181, `jqueryApp`). Both follow the existing app template exactly — federation config, retry/observability runtime plugins, Tailwind tokens, theme init + toggle, widget contract `mount(el) => unmount()`.

## What makes these two special
- **Zero framework plugins, zero shared deps.** Alpine and jQuery are imported directly; no `shared` config at all (self-contained by design, like Svelte/Lit). Simplest possible remotes — the "anything can federate" proof.
- **Alpine widget**: register `Alpine.data("mfAlpineWidget", …)` at module level (local state + nanostores subscriptions + `init`/`destroy` hooks), mount = inject the widget markup and `Alpine.initTree(root)`, teardown = `Alpine.destroyTree(root)` if available (guarded) + `root.remove()` — Alpine auto-disposes effects on DOM removal (documented). The widget never touches `window.Alpine` (only the Alpine host shell sets it, avoiding cross-copy clobbering).
- **jQuery widget**: build the widget DOM with `$()` + Tailwind classes, wire `.on("click")` handlers, teardown = `.off()` + `.remove()`; store subscription updates the shared value span. `@types/jquery` for TS.
- **Host shells in their own framework** (the point of the demo): the Alpine page is HTML-first (`x-data`/`x-for`/`x-text` markup in `index.html` driven by an `Alpine.data("mfShell")` component seeded from `@mf-all/app-registry`); the jQuery page is a single jQuery `render()` module with subscription-driven updates. Both get the full page anatomy (header + nav + theme toggle, hero, counter strip, 9-card grid, activity log).
